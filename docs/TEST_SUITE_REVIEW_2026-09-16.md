# Test suite review, 2026-09-16

**Scope.** 112 test files, 1,889 tests (1,753 unit, 134 integration, plus the Node middleware test). Four reviewers read every test file and the production code behind it, one per area; every finding they reported that this document repeats was re-checked against the code, and the ones with a live consequence were measured against the database. Verdicts per file are the reviewers'; cross-cutting findings and measurements are mine.

**Runs.** `pytest -m "not integration"`: 1,753 passed, 2 skipped, 89 s. Full suite with Postgres up and `READER_HTML=index.html`: 1,883 passed, 6 skipped, 3 min 55 s. Line coverage with everything running: 64.2% of `dcp/` (9,043 statements), 15.0% of `scripts/` (15,187). Unit suite alone: 56.5% and 15.0%.

## (a) Are the existing tests good?

Mostly yes, and unusually so for a project of this shape. Of 111 files reviewed: **88 sound, 20 weak, 3 problem.** The best files test a rule over the whole vocabulary rather than an instance, state the incident that produced them, and guard against their own vacuity (`test_tier_ordering.py`, `test_prose_counts_are_computed.py`, `test_drive_staging_shortfall.py`, `test_deepread_spool.py`, `test_zero_byte_guard.py`, `test_parties.py`, `test_signal_families.py`). Marker discipline is clean everywhere: no test touches `db_conn` without the `integration` marker.

The weaknesses are patterns, not scattered mistakes, and the same five recur across all four areas.

**1. Silent skips that make a test green on absence.** The repo's own lesson ("a guard that stops guarding is worse than none") is broken in five places:

- `tests/test_ea_permits.py:194` asserts `verify_ea_quotes() == []`, and `dcp/ea_permits.py:916` returns `[]` when the permit text is not on disk. `data/raw` is not committed, so on every CI run the 42 Environment Agency quotes are "verified" against nothing. The module docstring claims the test marks itself skipped; it does not.
- `tests/test_design_conformance.py:95-104`: `css_of` turns a missing selector into `pytest.skip`. 42 call sites, 10 of 20 tests. Renaming a class converts an assertion into a pass in the one file whose premise is catching rules that stopped applying.
- `tests/test_derivation.py:81-95`: the only integration test looks for a `power_adjudication` row, and the shared fixture truncates that table at the start of every test. It has skipped on every run since it was written. The `figure_derivations` idempotency contract has never executed.
- `tests/test_build_determinism.py:127`: `_normalise` never asserts the stamp regex matched. HISTORY records this exact regex silently matching nothing as one of three "guard that stops guarding" incidents; the pattern was fixed, the detector never added.
- `tests/test_reader_smoke.py:695` and `:747` are unmarked, so the unit job selects them, and `built_reader` skips rather than fails without a database. In CI's unit job they pass while asserting nothing (locally, with the container down, they were 2 of the 4 skips).

**2. Source-text grep as a proxy for behaviour.** Around forty assertions in fifteen files check that a substring appears in a `.py`, `.sql` or template file (`test_coverage_language.py` from line 662, `test_successor_hosts.py:56-69`, `test_held_but_empty.py:29`, `test_doncaster_docstore.py:60-81`, `test_reader_map.py`, `test_reader_sort_glyphs.py`, `test_reader_tip_301.py`, `test_facilities_sheet.py`, `test_excluded_applications_sheet.py`, `test_queue_reaches_adjacent_power.py:70`). They pass over broken behaviour that keeps the string and fail on harmless refactors; `test_coverage_language.py:267` already records one false alarm. `test_reader_map.py` greps 700-character windows and one guard sits at offset 637. Several read paths relative to the working directory, so the suite is only correct from the repo root.

**3. Fake cursors that discard the SQL.** `test_machine_reading.py:452` and `test_tier_scope.py:47` hand back fixture rows whatever query they receive. So none of the fold-to-latest queries (`LATEST_SQL`, `FIGURES_SQL`, `NOT_COUNTED_SQL`, `CLAIMS_SQL` in `dcp/machine_reading.py`; `compute_all` in `dcp/site_class.py`) and none of the read-cohort query in `scripts/deepread_run.py` is ever executed. Reversing an `ORDER BY` passes the suite. This is the class of error ("fold append-only tables to the latest row") that produced three wrong counts in one day in September.

**4. Curation pins mixed with rule pins.** `test_operator_rung.py:279` fails when a fourth campus is adjudicated; `test_ea_permits.py:34,222` pin 97 candidates and a 35/6/1 composition; `test_companies_house.py:32` hard-codes the over-merged site ids. `test_organisations.py:102` was deliberately rewritten away from this shape; the others were not.

**5. Duplication.** The docstore verdict test is copied four times, the prior-loader triad four times, `_sync()` and the fake Drive service twice, and `export_handover.py` is executed as a fresh module in three files. Ten test names repeat across files. All are fixture or parametrisation candidates for `conftest.py`.

Individually weak files, one line each: `test_smoke.py` tests its own fake; `test_fetch_outstanding_timeout.py:54` has no production code in it; `test_planit.py` never paginates; `test_external_aggregates.py:18-30` duplicates `check()`; `test_deepread_dry_run.py` reimplements the rule it reads; `test_regate_escalations.py:101` and `test_pages_sent_is_a_set.py:74` are named for a property the code does not have (below); `test_release_diff.py` covers `check_priors` only and feeds `<html></html>` to the one end-to-end call.

## (b) What has no test

Ranked by risk to the published numbers and to data integrity.

**1. CI runs neither the integration tests nor the exporters.** `.github/workflows/checks.yml` has no Postgres service and deselects the marker; the reader job drives the committed `index.html`. So the 134 tests that protect idempotency, dedup, membership retirement, clustering and the queue's scope only run on a laptop with the container up, and `scripts/export_reader.py` (7.5% unit coverage, 1,116 statements) and `scripts/export_handover.py` (13.6%) never execute in CI. A change that breaks a build passes every check; the reader tests confirm the *previous* build. The fix is a Postgres service in the unit job (the fixture already creates and migrates `dcp_test`) and a scratch build in the reader job.

**2. The test database is 21 migrations behind production.** `tests/conftest.py` applies 14 of 35 migrations by hand. Never applied: 012 (`findings_content_key`, the unique index that is the idempotency contract from the August duplicates fix), 023 (`site_machine_readings`), 025–027 (the audit and drawing stores), 031 (`document_drive_files`, the Drive-ID rule), 032 (`site_adjacent_power`), 033 (`gate_version`). No test anywhere references `findings_content_key`; `deepread_run.CONTENT_KEY` is a hand-maintained tuple that mirrors it and nothing checks the two agree. No test applies all 35 in order to a fresh database, so a migration that fails from scratch is found at restore time.

**3. The quote gate is written four times and tested once.** `scripts/deepread_run.py:520` is covered; `deepread_escalate.py:342`, `deepread_escalate_openai.py:1008` and `deepread_agent_escalate.py:267` each reimplement the candidate loop, the gate and the INSERT, untested. They have already drifted (see bugs, below). The pre-publication half of the round-trip rule, `scripts/verify_findings.py:280` onward (the status ladder, the exit code a gate would key on), is untested.

**4. No published number is tested end to end.** The masthead counts (`export_reader.py:6367-6379`) are Python; `#n` is filled by JavaScript from the DOM, so the smoke test's reconciliation is JS-internal. `SITE_FIGURE_SQL` and the largest-standing-figure rollup, which produce the number a reporter quotes, run in no test. Nothing compares a workbook figure with the reader's. `release_diff.reader_shape`'s five regexes, each with a recorded history of matching the wrong thing, are never asserted against a real page; a floor over the committed page (30 sections, 506 sites, a populated stamp) costs one test. Of 33,852 Drive links on the page, only the 212 operator-snapshot anchors are checked against the ledger.

**5. The adapters' fetch loops, for every family but Idox.** `ocella.py:385`, `arcus.py:259`, `agile.py:159`, `aifusion.py:164`, `ni_planning`, `salesforce_pr`: the listing classifiers are tested, the loops that set `links_found`, `downloaded`, `skipped_existing`, `errors` are not, and those four numbers are the whole input to the settled-verdict rule. The four docstore scripts' resume paths are untested. `acquisition_outcome` stores only `documents_found` and a sentence, so a wrong verdict cannot be audited afterwards.

**6. The editorial invariants.** Nothing tests that an external megawatt cannot reach a site's power cell by any path other than `rung_claim`, or that a scannable row shows tier and count rather than a raw MW (agreed 2026-08-20). `dcp/site_aliases.displayed` (the fix for three surfaces showing the misleading name) has its substituting branch never executed. `dcp/operator_disclosure.py`, whose output is the two-audiences story, has no test.

**7. Modules with no test at all, in order of consequence.** `scripts/backup_db.py` (460 lines: the one irreplaceable asset; `verify()` and `prune_local()` first). `dcp/operator_disclosure.py`. `scripts/computed_figures.py` (the A–D classifier that feeds the review sheet). `scripts/load_capacity_claims.py` (the batch-validates-whole contract). `scripts/export_pinpoint_bundle.py` (1,078 lines; `flat_name` and the drawing sniff). `dcp/signals.py` (the variant-forms rule `gas-fired ≡ gas fired` is pinned nowhere). `dcp/cli.py` (every subcommand resolves and `--help` exits 0). `dcp/entities.py`, `dcp/cohorts.py`, `dcp/corpus_stats.py`, `scripts/relist_refetch.py`, `scripts/retry_idox_errors.py`, `scripts/fetch_ea_permits.py`, `scripts/ingest_manual_docs.py`, the three `ch_*` generators behind the ownership file, `scripts/consumption_integrity.py`, `scripts/generation_integrity.py`. `dcp/reader.py` and `dcp/export.py` are the phase-1 path and the honest question is whether they should still be in the tree.

## Production defects found on the way

Each verified in the code; consequences measured where the database can show them.

1. **The read cohort includes applications that left their sites.** `scripts/deepread_run.py:323` is the only `JOIN site_members` in the codebase without `retired_at IS NULL` on the member row (27 others have it). Measured: **42 applications, 807 documents**, are in the cohort only through retired membership rows.
2. **The findings writers have drifted.** `deepread_escalate.py:358` and `deepread_agent_escalate.py:280` omit `signal_family` and `family_source` from their INSERT, the defect `backfill_signal_family.py` exists to repair; `_insert_agent` also omits the NUL strip the other three apply.
3. **The source-attribution query reads superseded adjudications.** `export_reader.py:3006-3018` picks which application a site's headline figure came from over `power_adjudication` raw, while the figure itself is folded to the latest row. Measured: 3,206 superseded `site_capacity` rows; 6 findings whose latest verdict is no longer `site_capacity`; 12 current attribution winners are superseded rows, every one identical in verdict and value to its latest. **The page is right today and exposed.**
4. **Ocella's download loop neither resumes nor counts.** `dcp/sources/ocella.py:472-506` never consults `held_bytes`, so every re-run re-downloads; and a document already on disk increments both `skipped_existing` and `downloaded`, so `held` can exceed `links_found` and a partial run classifies as `fetched`. Six other adapters share the tail but reach it only after a `prior` check. Not measurable from stored outcomes (point 5 above).
5. **Four docstore scripts keep the pre-guard held-bytes query.** `fetch_derby_docstore.py:143`, `fetch_neath_docstore.py:124`, `fetch_civica_docstore.py:194`, `fetch_newport_docstore.py:130` select without the `content_sha256 <> EMPTY_SHA256` clause that `repo.held_bytes` calls "the one place it lives now". Not yet bitten: the three zero-byte rows in the database are all on Idox routes.
6. **The neighbour-page rule contradicts its own docstring.** Both `deepread_run.verify_findings` and `regate_escalations.passes` try the claimed page ±1 whether or not those pages were sent to the model. The quote is verbatim on the page it cites, so provenance holds; `evidence_page` can name a page the model never saw, and the two tests named for the property pass on fixture geometry.
7. **The workbook build runs two of the five liveness checks the reader runs.** `export_handover.py:1546-1552` checks aliases and campus scope; `export_reader.py:2848-2879` also checks operator pages, facilities and held snapshots. A dead site key in `site_facilities.yaml` fails a reader build and passes a workbook build.
